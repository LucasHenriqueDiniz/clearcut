# Changelog

All notable changes to ClearCut are documented here. Versions follow
[semantic versioning](https://semver.org/); until 1.0 the minor number carries
breaking changes.

## v0.3.0 — 2026-08-19

### Frontend rebuilt on Vite

The frontend moved from Next.js to Vite + `@vitejs/plugin-react-swc`. ClearCut
is a single-screen desktop app with no server, so routing, SSR and the
`"use client"` boundary were cost without benefit. The main bundle dropped from
1129 KB to 627 KB, the dev server starts in ~350 ms and a production build takes
~2.5 s. Source now lives under `frontend/src/`.

Fonts are bundled from `@fontsource` packages instead of being fetched from
Google Fonts at runtime — the app's pitch is working offline, and that has to
include loading its own typeface.

### Workspace you can actually start from

- **Navigation is reachable again.** Settings had no entry point; the header now
  carries Workspace / History / Settings. Models and Providers moved under
  Settings, where they belong — they are things you configure, not places you
  work.
- **Panes now switch.** `AnimatePresence mode="wait"` was holding the outgoing
  pane forever, so the app could get stuck on a screen. Fixed.
- **Modes first, options second.** A job starts from *Remove background*,
  *Optimize images* or *Remove and upscale*. The thirty individual controls are
  still all there, behind an "Advanced options" disclosure.
- **Options show what they do.** Six controls carry a before/after tile split on
  the diagonal. The images are generated by
  `backend/scripts/generate_option_previews.py`, which runs the real pipeline
  twice per option — off and on, everything else equal — so a thumbnail cannot
  claim an effect the code does not produce.
- **One control was lying.** "Alpha matting" actually applied a destructive alpha
  threshold. It is now labelled "Drop faint pixels".
- The footer was rebuilt, and the displayed version is read from
  `package.json` at build time instead of being hardcoded.

### Testing

`backend/scripts/smoke_batch.py` drives a running backend over HTTP once per
mode and asserts the output format, transparency and upscale factor.

## v0.2.0 — 2026-08-18

- Frontend types are generated from the backend's OpenAPI document
  (`npm run gen:api`), so the contract can no longer drift by hand.
- Jobs process files in parallel — up to `min(4, cores-1)` per job, capped
  process-wide by a semaphore. Roughly 1.3–1.4× on real batches.
- rembg sessions live in a bounded LRU pool with a per-model build lock instead
  of a single global session. Cold job time went from 8.29 s to 2.93 s.
- Frontend polling is cancellable: it aborts in-flight requests, cancels on
  unmount and supersedes a previous poll.
- `AGENTS.md` documents the invariants for coding agents; README and the UI are
  in English.
